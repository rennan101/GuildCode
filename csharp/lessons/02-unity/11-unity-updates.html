11. Ciclo de Vida — Update, FixedUpdate e LateUpdate

Módulo 2 — Fundamentos do Unity

O Unity executa metodos automaticamente em momentos especificos. Conhecer o ciclo de vida e essencial para saber onde colocar cada tipo de codigo.

11.1 — Ordem de Execucao

public class CicloDeVida : MonoBehaviour
{
    // 1. AWAKE — chamado QUANDO O OBJETO E CRIADO (antes do Start)
    void Awake()
    {
        Debug.Log("1. Awake: Objeto criado!");
    }

    // 2. START — chamado UM UNICA VEZ, antes do primeiro Update
    void Start()
    {
        Debug.Log("2. Start: Vai comecar!");
    }

    // 3. UPDATE — chamado TODOS OS FRAMES (60x por segudo em media)
    void Update()
    {
        // Logica geral, input, animacoes
    }

    // 4. FIXEDUPDATE — chamado em intervalos FIXOS (50x por segundo)
    void FixedUpdate()
    {
        // Logica de FISICA (Rigidbody, AddForce, etc.)
    }

    // 5. LATEUPDATE — chamado DEPOIS de todos os Updates
    void LateUpdate()
    {
        // Camera follow, ajustes finais
    }

    // 6. ONDESTROY — chamado quando o objeto e DESTRUIDO
    void OnDestroy()
    {
        Debug.Log("6. OnDestroy: Objeto destruido!");
    }
}
Passo a passo no Editor:
1. Crie um GameObject vazio e adicione este script
2. Clique em Play — veja Awake e Start
3. Pare o Play — veja OnDestroy
4. Observe: Update e chamado 60 vezes por segundo!
Saida esperada ao clicar Play:
1. Awake: Objeto criado!
2. Start: Vai comecar!
... (Update repetindo continuamente) ...

11.2 — Awake vs Start

// Awake: roda quando o objeto nasce
// Start: roda NA PRIMEIRA VEZ que o Update seria chamado
// Diferenca: se voce tem 2 scripts, todos os Awakes rodam PRIMEIRO,
// depois todos os Starts rodam. Isso garante que referencias existam.

public class Configurador : MonoBehaviour
{
    public static int contador;

    void Awake()
    {
        contador++; // Executa para TODOS os objetos antes de qualquer Start
    }
}

public class Usador : MonoBehaviour
{
    void Start()
    {
        // Pode usar o contador porque todos os Awakes ja rodaram
        Debug.Log($"Total de configuradores: {Configurador.contador}");
    }
}
Regra simples:
• Awake() → Inicializar proprias referencias, singletons
• Start() → Acessar objetos de OUTROS scripts (garantido que existem)
• Update() → Input, movimento, animacao, logica geral
• FixedUpdate() → FISICA (Rigidbody, colisoes, forcas)
• LateUpdate() → Camera follow (so move a camera DEPOIS do player ter se movido)

11.3 — FixedUpdate para Fisica

// POR QUE nao usar Update para fisica?
// Porque Update roda em frame rates variaveis (30, 60, 144 FPS)
// Mas a fisica precisa de intervalos FIXOS para ser consistente!

public class ExemploFisica : MonoBehaviour
{
    private Rigidbody rb;

    void Start()
    {
        rb = GetComponent<Rigidbody>();
    }

    // FixedUpdate roda 50x por segundo (padrao), independente do FPS
    void FixedUpdate()
    {
        rb.AddForce(Vector3.forward * 10f);
    }
}

11.4 — LateUpdate para Camera Follow

// Camera que segue o player
public class CameraFollow : MonoBehaviour
{
    [SerializeField] private Transform alvo;
    [SerializeField] private Vector3 offset = new Vector3(0, 5, -10);
    [SerializeField] private float suavidade = 5f;

    // LateUpdate roda DEPOIS do Update do player
    // Isso evita "stuttering" (trepidez) na camera
    void LateUpdate()
    {
        if (alvo == null) return;

        Vector3 posicaoAlvo = alvo.position + offset;
        transform.position = Vector3.Lerp(
            transform.position,
            posicaoAlvo,
            suavidade * Time.deltaTime
        );
    }
}
Passo a passo no Editor:
1. Crie um Cube nomeado "Player" e um Cube nomeado "Camera"
2. Adicione CameraFollow ao Cube Camera
3. No Inspector, arraste o Player para o campo "Alvo"
4. Mova o Player com um script de movimento
5. Observe: a camera segue suavemente!
Dica do Professor: Se voce tem stuttering (objeto treme enquanto se move), provavelmente esta usando Update para algo que deveria estar em LateUpdate (como camera follow) ou FixedUpdate (como fisica).
Atividade Pratica no Unity:
1. Crie um script que mostre Time.frameCount e Time.deltaTime no Console
2. Observe: FrameCount aumenta rapido,DeltaTime varia entre 0.016 (60FPS) e 0.033 (30FPS)
3. Crie uma camera que siga o player em LateUpdate
4. Mova o player e observe o movimento suave da camera
Saida esperada no Console (exemplo com 60FPS):
Frame: 1 | DeltaTime: 0.0167
Frame: 2 | DeltaTime: 0.0165
Frame: 3 | DeltaTime: 0.0168

DESAFIO DO MODULO 2 — Plataforma Movel

Crie uma plataforma que se move de um ponto a outro, usando o que voce aprendeu!

Requisitos:
1. Crie um Cube como "plataforma" (scale X=3, Y=0.5, Z=3)
2. Crie um Player (Capsule + Rigidbody + script de movimento WASD)
3. Crie um script PlataformaMovel que:
   • Use Update() para mover a plataforma entre dois pontos usando Vector3.Lerp()
   • Use [SerializeField] Transform pontoA e Transform pontoB
   • Use [SerializeField] float velocidade = 2f
4. Crie 2 GameObjects vazios como pontos A e B
5. Ao pular na plataforma, o player deve se mover junto com ela
Resultado esperado:
• A plataforma vai e volta entre os pontos A e B
• O player pode pular nela e se mover junto
• A camera segue o player suavemente via LateUpdate
